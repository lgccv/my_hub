# 四相机标定算法思路与优缺点

## 1. 算法目标

这个脚本的目标是计算四个相机在机器人 `base` 坐标系下的外参，也就是每个相机的：

```text
T_base_camera_link
```

结果会写入 `multi_cam_result.yaml`，里面包含每个相机相对于 `base` 的平移和四元数。

当前脚本处理的是四个相机：

```text
cam_front
cam_right
cam_back
cam_left
```

每个相机绑定一个对应的 FM marker：

```text
cam_front -> FRACTAL_MARKER_2L_0
cam_right -> FRACTAL_MARKER_2L_1
cam_back  -> FRACTAL_MARKER_2L_2
cam_left  -> FRACTAL_MARKER_2L_3
```

## 2. 整体思路

这套算法的核心思想是：提前知道标定夹具和机器人之间的固定几何关系，然后用相机观测到 marker 的位姿，反推出相机在机器人 `base` 坐标系下的位置和朝向。

整体坐标链路是：

```text
base -> fm0 -> 当前 marker -> camera
```

也就是说，程序需要知道三段关系：

```text
1. base -> fm0
2. fm0 -> 当前 marker
3. 当前 marker -> camera
```

前两段来自代码里的固定配置，第三段来自 FM marker 检测结果。

## 3. 关键配置

### 3.1 base 到 fm0 的关系

`build_base_fm0_pose()` 写死了 `fm0` 在机器人 `base` 坐标系下的位姿：

```python
R_base_fm0, t_base_fm0 = build_base_fm0_pose()
```

其中：

```text
R_base_fm0 表示 fm0 相对于 base 的旋转
t_base_fm0 表示 fm0 相对于 base 的平移
```

这一步是整个标定链路的基准。如果这个值不准，所有相机的外参都会一起被带偏。

### 3.2 marker 之间的关系

`build_fixture_and_bindings()` 里定义了四个 marker 在标定夹具 `jig` 坐标系下的位置和姿态：

```text
fm0: 前方 marker，对应 cam_front
fm1: 右侧 marker，对应 cam_right
fm2: 后方 marker，对应 cam_back
fm3: 左侧 marker，对应 cam_left
```

程序会把这些 marker 在 `jig` 下的位姿转换成相对于 `fm0` 的位姿：

```text
R_fm0_fm
t_fm0_fm
```

这些关系保存在 `jig_markers` 里。

### 3.3 相机和 marker 的绑定

同一个函数还会生成 `cameras`，它表示每个相机应该使用哪个 marker，以及使用哪套相机内参。

例如：

```text
cam_front -> FRACTAL_MARKER_2L_0 -> front_camera 内参
cam_right -> FRACTAL_MARKER_2L_1 -> right_camera 内参
cam_back  -> FRACTAL_MARKER_2L_2 -> back_camera 内参
cam_left  -> FRACTAL_MARKER_2L_3 -> left_camera 内参
```

所以：

```text
jig_markers 负责描述 marker 之间的空间关系
cameras 负责描述相机、marker、内参之间的绑定关系
```

## 4. 数据处理流程

### 4.1 加载图片帧

`load_buffered_frames()` 会从四个图片目录里加载图片路径：

```text
front_image
right_image
back_image
left_image
```

每个相机最多取 50 帧。

然后 `validate_buffered_input()` 会检查每个相机至少有 10 帧图片，否则直接失败。

### 4.2 加载预计算 FM 检测结果

当前脚本不在 Python 里直接做 marker 检测，而是读取提前生成好的 JSON：

```text
data/fm_code_json/cam_front.json
data/fm_code_json/cam_right.json
data/fm_code_json/cam_back.json
data/fm_code_json/cam_left.json
```

每个 JSON 里保存每一帧检测到的 marker 位姿：

```text
R_cam_marker
t_cam_marker
```

也就是 marker 在相机坐标系下的位置和朝向。

### 4.3 逐帧收集有效观测

主流程会遍历每个相机、每一帧图片：

```python
for cam in cfg.cameras:
    for i, image_path in enumerate(frames_by_camera[cam.camera_id]):
        process_frame(...)
```

`process_frame()` 会根据帧号从预计算 JSON 中找到检测结果，然后优先选择当前相机绑定的 marker。

如果这一帧有可用 marker 观测，就把它保存到：

```text
CameraObservationSet.frames
```

最后会统计：

```text
processed: 处理了多少帧
accepted: 接受了多少帧有效观测
```

### 4.4 多帧融合

`fuse_camera_observations()` 会把同一个相机的多帧观测融合成一个稳定结果：

```text
R_cam_fm_fused
t_cam_fm_fused
```

融合方式是：

```text
1. 用平移距离判断离群帧
2. 去掉平移离群帧
3. 对有效帧的平移取平均
4. 对有效帧的四元数做线性平均并归一化
```

当前平移离群阈值是：

```text
0.05 m
```

也就是距离均值超过 5 cm 的帧会被认为是异常帧。

### 4.5 计算相机外参

`compute_camera_extrinsic()` 是最终求外参的核心函数。

FM 检测得到的是：

```text
T_cam_fm
```

也就是 marker 在相机坐标系下的位姿。

但是要求相机在 marker 坐标系下的位姿，所以先取逆：

```text
T_fm_cam = inverse(T_cam_fm)
```

代码对应：

```python
R_fm_cam = obs.R_cam_fm_fused.T
t_fm_cam = -R_fm_cam @ obs.t_cam_fm_fused
```

然后按坐标链路计算：

```text
T_base_camera = T_base_fm0 * T_fm0_fm * T_fm_cam
```

旋转部分：

```python
R_base_camera_optical = R_base_fm0 @ R_fm0_fm @ R_fm_cam
```

平移部分：

```python
t_base_camera_optical =
    R_base_fm0 @ (R_fm0_fm @ t_fm_cam + t_fm0_fm)
    + t_base_fm0
```

最后脚本还会把结果从相机 optical 坐标系转换到 camera link 坐标系：

```text
camera_optical -> camera_link
```

这里默认 optical 和 link 原点相同，只是朝向不同，所以平移不变，旋转会乘一个固定转换矩阵。

## 5. 输出结果

每个相机最终输出：

```text
camera_id
marker_code
num_observations
num_outliers
T_base_camera_link
```

其中 `T_base_camera_link` 包含：

```text
quat: 相机 link 坐标系相对于 base 的旋转
xyz:  相机 link 坐标系相对于 base 的平移
```

这些结果会写入：

```text
multi_cam_result.yaml
```

## 6. 优点

### 6.1 流程简单，容易理解

这套方案的坐标链路很清楚：

```text
base -> fm0 -> marker -> camera
```

每一步都是刚体变换拼接，代码实现直接，便于调试。

### 6.2 不需要复杂优化器

当前脚本不需要非线性优化、bundle adjustment 或手眼标定求解器。

只要：

```text
1. 已知 base -> fm0
2. 已知 fm0 -> marker
3. 能检测出 camera -> marker
```

就可以直接算出每个相机外参。

### 6.3 多帧平均可以降低随机噪声

单帧 marker 检测可能有抖动。脚本使用多帧结果做融合，可以降低随机检测噪声。

对于相机固定、marker 固定、图片质量稳定的情况，这种平均方式能让结果更平稳。

### 6.4 可复现性比较好

脚本读取固定图片和固定 JSON 结果，输出过程确定性比较强。

只要输入数据不变，结果基本可以复现，适合离线调试和对比不同算法版本。

### 6.5 工程依赖少

Python 侧主要做数据读取、姿态融合和矩阵计算。marker 检测结果已经提前保存成 JSON，运行时不强依赖检测后端。

这对排查问题比较友好：检测问题和外参计算问题可以分开看。

## 7. 缺点和风险

### 7.1 强依赖 base 到 fm0 的先验

`base -> fm0` 是提前写死的。

如果这个值来自人工测量、CAD 理论值或历史标定结果，只要它不准，最终四个相机的外参都会整体偏掉。

常见影响包括：

```text
1. fm0 的平移误差会直接传给所有相机
2. fm0 的旋转误差会放大到每个相机的朝向和位置上
3. 四个相机可能整体看起来一致，但相对于机器人 base 是错的
```

这是这套方案最大的系统误差来源之一。

### 7.2 强依赖 marker 之间的固定几何关系

四个 marker 在夹具上的位置和姿态也是提前写死的。

如果实际夹具有加工误差，或者 marker 贴歪、贴偏、板面不平，那么：

```text
fm0 -> fm1
fm0 -> fm2
fm0 -> fm3
```

这些关系就不是真实值。

结果是：

```text
cam_right、cam_back、cam_left 会继承对应 marker 的安装误差
```

相比之下，`cam_front` 直接绑定 `fm0`，它受到 marker 间相对关系误差的影响较小。

### 7.3 每个相机基本只由一个 marker 约束

当前绑定关系是一对一：

```text
一个相机 -> 一个 marker
```

这会导致某个 marker 的检测误差或安装误差很难被其它观测纠正。

更稳的方案通常希望：

```text
1. 一个相机能看到多个 marker
2. 一个 marker 能被多个相机看到
3. 所有观测一起做联合优化
```

这样才能用冗余观测互相约束。

### 7.4 多帧融合只能降低随机误差，不能消除系统误差

当前多帧融合主要是平均。

它能缓解检测抖动，但不能解决这些问题：

```text
1. 相机内参不准
2. 畸变参数不准
3. marker 尺寸不准
4. base -> fm0 不准
5. marker 间安装关系不准
6. 标定夹具不是刚体或存在变形
```

这些都属于系统误差，平均更多帧也不会真正消掉。

### 7.5 离群判断比较粗

当前离群判断主要看平移，阈值是 5 cm。

这个策略比较简单，风险是：

```text
1. 旋转异常不一定能被发现
2. 重投影误差大的帧不一定会被剔除
3. 5 cm 阈值对高精度外参来说偏宽
4. 不同相机、不同距离下使用同一个阈值不一定合理
```

如果目标是厘米级甚至毫米级标定，这个离群策略还不够精细。

### 7.6 没有输出质量评估指标

当前输出主要是最终外参和离群数量。

缺少这些验收指标：

```text
1. 每帧重投影误差
2. 每个相机的平移标准差
3. 每个相机的旋转标准差
4. marker 检测置信度统计
5. 多相机之间的闭环一致性误差
```

所以脚本显示 `success=true`，只能说明流程跑通，不代表标定结果一定准确。

### 7.7 相机内参被写死

`build_camera_intrinsics()` 给四个相机使用同一套内参和畸变参数。

如果四个相机实际内参不同，或者某个相机重新对焦、换镜头、换分辨率，那么检测出来的 marker 位姿会偏，最终外参也会偏。

## 8. 更稳的改进方向

### 8.1 单独高精度标定夹具

可以先用更高精度的方法测量四个 marker 的真实相对位姿，然后替换代码里的理论值。

这样可以减少：

```text
fm0 -> fm1/fm2/fm3
```

这部分先验误差。

### 8.2 把 base -> fm0 也作为待优化变量

不要完全相信写死的 `base -> fm0`，而是把它当作一个初值。

后续通过多相机、多帧、多 marker 观测一起优化：

```text
base -> fm0
fm0 -> marker_i
base -> camera_i
```

这样可以减少单个先验错误对最终结果的影响。

### 8.3 让每个相机看到多个 marker

如果视野允许，可以让每个相机同时看到多个 marker。

这样一个相机的外参就不只依赖一个 marker，结果会更稳定，也更容易发现单个 marker 的安装或检测异常。

### 8.4 引入全局最小二乘优化

把所有帧、所有相机、所有 marker 的观测放到一个优化问题里，最小化重投影误差或位姿残差。

优化目标可以类似：

```text
最小化所有观测中的 marker 重投影误差
```

或者：

```text
最小化观测位姿和预测位姿之间的 SE(3) 残差
```

这种方式比单纯平均更能处理噪声和冗余约束。

### 8.5 输出更完整的标定质量报告

建议最终输出除了外参，还要输出：

```text
1. 每个相机使用了多少帧
2. 每个相机剔除了多少异常帧
3. 每个相机的平均重投影误差
4. 每个相机的最大重投影误差
5. 平移标准差
6. 旋转标准差
7. 每个 marker 的观测次数
```

这样才能判断结果是“跑通了”，还是“真的可靠”。

## 9. 总结

当前算法是一套基于固定夹具先验的四相机外参计算方案。

它的优点是简单、直接、容易复现，适合在已知夹具几何很准、`base -> fm0` 很准、marker 检测稳定的条件下快速计算外参。

它的主要缺点是强依赖两个先验：

```text
1. base -> fm0 的关系
2. marker 之间的关系
```

这两个先验只要有误差，最终相机外参就会继承误差。当前多帧平均只能降低随机噪声，不能消除这些系统误差。

如果要提升精度和可信度，推荐把这套方案从“固定几何链路直接计算”，升级成“多相机、多 marker、多帧联合优化”，并输出完整的残差和质量评估指标。
